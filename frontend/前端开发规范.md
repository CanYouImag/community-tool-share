# 邻租平台 · 前端开发规范

> 本文档是「邻租」社区闲置工具租赁平台前端工程的开发约定，作为路由、请求封装、组件、Mock 数据的统一标准。由界面设计员负责维护；后续后端 API 就绪后仅需替换 Mock 层，其余约定不变。

## 一、技术栈

- **框架**：Vue 3（Composition API + `<script setup>`）
- **构建**：Vite
- **路由**：Vue Router 4（Hash 模式）
- **状态**：Pinia
- **请求**：Axios（统一封装）
- **样式**：沿用原型的 `common.css` 设计系统（绿色系 OKLCH 变量），不引入第三方 UI 组件库
- **Mock**：Axios 拦截器 + 本地 JSON 假数据，接口就绪后移除拦截器即可切换真实后端

## 三、命名规范

| 对象          | 规范                     | 示例                             |
| ------------- | ------------------------ | -------------------------------- |
| 组件文件      | PascalCase，多词         | `ItemCard.vue`、`AppTopbar.vue`  |
| 视图文件      | PascalCase，以 View 结尾 | `CommunityView.vue`              |
| 页面路由 path | kebab-case               | `/order-detail/:id`              |
| 变量/函数     | camelCase                | `orderList`、`fetchOrders`       |
| 常量          | UPPER_SNAKE_CASE         | `ORDER_STATUS`                   |
| CSS 类        | 沿用原型语义类名         | `.panel`、`.item-card`、`.badge` |

## 四、路由规范

- 采用 Hash 模式（`createWebHashHistory`），便于静态部署与演示。
- 顶部导航（物品广场/社区/发布/订单/钱包/个人中心）为全局常驻，通过 `AppTopbar` 渲染，`active` 状态由当前路由匹配。
- 本阶段实现的页面路由：

| path                | 组件            | 说明                       |
| ------------------- | --------------- | -------------------------- |
| `/community`        | CommunityView   | 社区（发现/主页/我的社区） |
| `/orders`           | OrdersView      | 我的订单                   |
| `/order-detail/:id` | OrderDetailView | 订单详情与操作             |
| `/wallet`           | WalletView      | 钱包                       |
| `/dispute`          | DisputeView     | 纠纷与举报                 |

## 五、请求封装规范

- 所有请求统一走 `src/api/request.js` 导出的 `http` 实例。
- 约定后端返回统一结构：`{ code, message, data }`，`code === 0` 表示成功。
- 请求拦截器统一注入 `Authorization` token（后续对接 JWT）。
- 响应拦截器统一处理 `code !== 0` 的错误提示。
- **Mock 阶段**：在 `request.js` 的请求拦截器里，当 `VITE_USE_MOCK === 'true'` 时按 `method + url` 匹配 `mock/index.js` 中的处理器返回假数据；接口就绪后置该开关为 `false`，请求即透传到真实后端，业务代码无需改动。

## 六、组件约定

- 公共组件放 `src/components/`，业务组件就近放视图目录。
- 组件通过 `props` 接收数据、`emits` 抛事件，不直接访问 store 或发起请求（容器视图负责取数）。
- 状态徽章统一用 `StatusBadge`，传入 `status` 自动映射文案与颜色类，保证状态文案与原型/需求一致。

## 七、Mock 数据约定

- 假数据集中在 `src/api/mock/data.js`，字段命名与 4.4 节数据需求实体对齐。
- 状态枚举与文案统一从 `utils/constants.js` 读取，避免页面内散落魔法字符串。
- Mock 处理器返回 Promise + 200ms 延迟，模拟真实网络。

## 八、状态字典（与需求对齐）

订单状态：`PENDING`（待确认）/ `PAID`（确认支付）/ `TO_PICKUP`（待取物）/ `RENTING`（租用中）/ `TO_RETURN`（待归还确认）/ `COMPLETED`（已完成）/ `CANCELLED`（已取消）/ `DISPUTING`（纠纷中）/ `CLOSED`（已终结）。

纠纷状态：`MEDIATING`（调解中）/ `PENDING_ARBITRATION`（待仲裁）/ `RESOLVED`（已调解）/ `ARBITRATED`（已裁决）。

流水类型：`INCOME`（收入）/ `EXPENSE`（支出）/ `FREEZE`（冻结）/ `UNFREEZE`（解冻）。
