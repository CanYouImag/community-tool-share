## 一、项目背景与目标
### 1.1 项目背景
社区居民普遍持有大量低频使用的工具（电钻、梯子、帐篷、投影仪、童车等），存在“买着贵、用一次、占地方”的痛点；另一方面，临时有需求的邻居面临“购买不划算、借用欠人情”的困境。甲方希望通过搭建**社区闲置工具租赁平台**，实现：
- 盘活社区闲置资产，倡导绿色共享消费
- 增强社区邻里互动与信任
- 沉淀社区数字化运营能力，形成可持续的商业模型
### 1.2 产品定位
**以真实社区（小区/商圈/园区）为单位的双边租赁平台**，强调“同社区、可自提、可面交”的近距离信任交易，区别于异地快递租赁平台。
### 1.3 项目目标（验收导向）
| 阶段     | 时间              | 核心目标                                           |
| -------- | ----------------- | -------------------------------------------------- |
| MVP 上线 | 合同生效后 4 个月 | 完成 1 个试点社区，注册用户 ≥ 500，认证用户 ≥ 200  |
| 运营验证 | 上线后 3 个月     | 月成交订单 ≥ 300 单，物品复租率 ≥ 30%，纠纷率 ≤ 2% |
| 规模复制 | 上线后 12 个月    | 覆盖 ≥ 20 个社区，具备社区自助开通能力             |

## 二、用户角色与权限体系（核心）
### 2.1 角色定义
系统采用**“功能与身份解耦”**的设计：出租与租用是认证用户的两个功能，不作为独立角色。角色按权限等级划分：
```
游客 → 注册用户 → 认证用户（双向交易）→ 社区管理员（局部治理）→ 系统管理员（全局治理+资金）
```
| 角色       | 说明                           | 获取方式                             |
| ---------- | ------------------------------ | ------------------------------------ |
| 游客       | 未注册访客，仅可浏览           | 无需操作                             |
| 注册用户   | 完成手机号注册                 | 手机号+验证码                        |
| 认证用户   | 完成实名认证，解锁全部交易功能 | 身份证信息 + 平台审核                |
| 社区管理员 | 负责单个社区的日常治理         | 社区创建者 / 成员推选 + 平台审核任命 |
| 系统管理员 | 平台运营方员工，全局治理       | 后台账号授权，禁止参与交易           |
### 2.2 权限矩阵（RBAC，乙方需严格实现）

| 浏览/搜索物品       |  ✅   |    ✅     |      ✅      |      ✅      |     ✅      |

### 2.3 权限设计硬性要求
1. **资金权限零下放**：社区管理员不得触碰任何押金、退款、提现操作，只能提交仲裁申请+证据。
2. **数据行级隔离**：社区管理员所有查询接口强制附带 `community_id` 过滤，接口层杜绝越权。
3. **操作留痕**：社区管理员及系统管理员的全部管理操作（踢人、下架、仲裁等）必须记录操作日志，日志保留 ≥ 2 年。
4. **申诉通道**：被社区管理员处置的用户可向系统管理员申诉，申诉需在 3 个工作日内处理。

## 三、功能需求
### 3.1 用户端（小程序 + App）
#### F1 账户模块
- F1.1 手机号注册/登录（验证码），支持微信授权快捷登录
- F1.2 实名认证：提交姓名+身份证号+人脸识别，对接三方认证接口，审核结果 T+1 内反馈
- F1.3 个人中心：我的物品、我的订单、收藏、收入钱包、信用分、消息通知
- F1.4 信用分体系（V1.0 简化版）：初始分 80，按时归还+好评加分，逾期/违约/纠纷败诉扣分；**信用分 < 60 禁止发布高价值物品（押金 > 500 元），< 40 禁止下单**
#### F2 物品模块
- F2.1 物品发布：照片（≥3张，支持视频≤30秒）、标题、描述、品类、成色说明、租金定价（支持按天/按周阶梯价）、押金金额、可租时段、取还方式（自提/面交/送货）
- F2.2 物品发布后进入**待审核**状态，社区管理员初审+系统自动违禁词检测，通过后上架
- F2.3 搜索与筛选：关键词、品类、价格区间、距离、信用分、评分排序
- F2.4 物品详情页：多图浏览、租期日历（显示已被占用时段）、出租者信用与历史评价、押金说明、同类物品比价
- F2.5 上下架管理：出租者可随时暂停/恢复出租
#### F3 订单模块（核心交易流程）
- F3.1 流程：选物品 → 选租期 → 支付（租金+押金，押金平台托管）→ 出租者确认接单 → **取物核销（扫码+拍照存证）** → 使用期 → **还物核销（扫码+拍照存证）** → 出租者确认归还 → 押金解冻 → 双向评价
- F3.2 取/还物时**强制拍照存证**（前后状态对比），照片作为纠纷仲裁证据，保存 ≥ 1 年
- F3.3 订单状态：待确认、待取物、租用中、待归还、待确认、已完成、纠纷中、已取消
- F3.4 逾期处理：逾期自动提醒；逾期 > 24 小时按日加收租金（费率出租者可设）；逾期 > 72 小时触发仲裁流程
- F3.5 站内沟通：订单内嵌聊天，敏感词过滤，禁止引导线下交易脱钩（检测手机号/微信号提示风险）
#### F4 支付与资金模块
- F4.1 对接微信支付（甲方指定），押金托管于平台账户
- F4.2 归还确认后，租金扣除平台佣金（默认 10%，可后台配置）后进入出租者钱包
- F4.3 钱包提现：T+1 到账，单笔限额，需实名认证；提现记录可查
- F4.4 纠纷冻结：仲裁期间相关订单资金冻结，裁决后按结果划转
#### F5 社区模块
- F5.1 社区列表与搜索（按地理位置推荐附近社区）
- F5.2 加入社区：选择社区 → 社区管理员审核（可配置为自动通过）
- F5.3 社区主页：公告、热门物品、新上架物品、社区成员数与交易统计
- F5.4 社区动态：成员可发布求租信息、共享使用技巧（轻社区内容）
- F5.5 跨社区规则：默认只能与**同社区**成员交易（V1.0）；后续版本可开放“附近社区”选项
#### F6 评价与纠纷模块
- F6.1 双向评价：1-5 星 + 文字 + 图片，订单完成后 7 天内有效
- F6.2 举报入口：物品、用户、评价均可举报，附证据
- F6.3 纠纷流程：发起方提交凭证 → 社区管理员 48 小时内调解 → 调解不成或涉资金 → 上报系统管理员仲裁（5 个工作日内裁决）→ 双方查看裁决书
- F6.4 仲裁裁决类型：全额退押金、扣除部分赔偿、扣除全额、租金减免
### 3.2 社区管理员端（小程序内嵌管理界面）
- F7.1 成员管理：成员列表（昵称、活跃度、社区内信用）、踢出/拉黑（仅本社区）、处理加入申请
- F7.2 物品管理：待审核队列（初审）、违规下架、置顶推荐（同时最多 3 个）
- F7.3 社区运营：发布公告（文字+图片）、配置社区准入规则
- F7.4 纠纷调解工作台：查看纠纷双方凭证、留言调解、上报仲裁
- F7.5 社区数据看板：本社区交易量、GMV、热门品类、纠纷率、活跃成员数（周/月维度）
- F7.6 **所有管理操作均需留日志并不可删除**
### 3.3 系统管理员端（Web 后台）
- F8.1 用户治理：认证审核、账号封禁/解封、黑名单、信用规则配置
- F8.2 社区治理：社区创建审批、社区管理员的任命/审核/罢免、处理针对社区管理员的投诉
- F8.3 内容治理：全局违禁品库与违禁词库、跨社区物品审核终审、批量下架
- F8.4 仲裁中心：接收社区上报案件、查看全量证据、裁决押金归属、生成裁决书
- F8.5 资金管理：佣金比例配置、提现审批、退款操作、可疑资金冻结、对账报表
- F8.6 运营配置：品类管理、Banner、全局公告、优惠券/新人免押额度
- F8.7 数据看板：全平台 GMV、订单趋势、社区健康度排名、用户留存、复租率
- F8.8 系统管理：员工账号与角色分配（后台需细分：客服只读、运营可配置、超管全权限）、操作日志审计

## 四、非功能性需求
| 类别   | 要求                                                         |
| ------ | ------------------------------------------------------------ |
| 性能   | 页面加载 ≤ 2s；搜索响应 ≤ 500ms；支持 1 万并发在线           |
| 可用性 | 核心服务可用性 ≥ 99.9%；资金相关操作不可用需明确降级提示     |
| 安全   | 用户敏感信息（身份证、手机号）加密存储，展示脱敏；支付符合 PCI 相关规范；接口防越权（每个接口校验角色+数据归属） |
| 合规   | 遵守《个人信息保护法》《电子商务法》；隐私政策与用户协议上线前过法务审核；押金托管方案需符合地方预付资金监管要求（乙方配合提供方案） |
| 兼容   | 微信小程序（主要载体）+ H5；后台支持 Chrome/Edge             |
| 数据   | 全量操作日志与交易数据保留 ≥ 2 年；提供基础数据导出（Excel） |

1. **功能验收**：按本需求文档 3.x 各模块逐条验收，乙方需提供测试用例文档并配合甲方 UAT 测试
